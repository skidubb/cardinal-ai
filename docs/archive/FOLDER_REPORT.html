02Core Projects

Four production-grade applications plus supporting research and recursive-loop scaffolding.

CE - Agent BuilderPython CLI

▾

The agent factory. A Python CLI app (csuite) hosting 7 executive AI agents — CEO, CFO, CTO, CMO, COO, CPO, CRO — with role-specific tools, MCP integrations, and Pinecone memory. Prompts + tools + memory live here; orchestration consumes them via ServerAgent.

  • 80 role system prompts in agents/sdk_agent.py:_ROLE_PROMPTS
  • 27 tool schemas in tools/schemas.py:ALL_TOOL_SCHEMAS
  • Per-role tool mappings for 66 roles in tools/registry.py
  • Two backends: BaseAgent (direct Anthropic) and SdkAgent (Claude Agent SDK)
  • DuckDB learning store + session persistence + evaluation reports

Sample Commands

csuite ceo "should we raise a Series B?"
csuite synthesize "Q4 strategy" -a cfo cto
csuite debate "build vs buy" -a cfo cto cmo -r 3
csuite audit --revenue "$12M" --employees 45
Anthropic SDK Pinecone DuckDB Hatchling

CE - Multi-Agent OrchestrationFastAPI + React

▾

The protocol engine. 57 coordination protocols and a 62-agent registry exposed through a FastAPI engine with a React frontend, deployed on Railway. Each protocol is self-contained: orchestrator.py, prompts.py, run.py.

Categories

Liberating Structures Intelligence Tradecraft TRIZ Game Theory Systems Thinking Philosophical Reasoning Multi-Round Debate Decentralized Coordination

Production Notes

  • ServerAgent — Docker-safe agent class, direct AsyncAnthropic + native tool loop, max 15 iterations
  • Two model tiers: Opus for reasoning, Haiku for orchestration
  • --mode research falls back to lightweight dicts; production is default
  • SSE streaming for live run progress, WeasyPrint PDF reports
  • Langfuse tracing + Postgres persistence (both degrade gracefully)

CE - EvalsPython library

▾

Library-only LLM-as-judge evaluation framework. No CLI — imported programmatically. Lives in src/ce_evals/core/: judge.py + judge_backends.py (Claude / GPT-4 / Gemini), rubric.py, runner.py, cost.py.

Claude judge GPT-4 judge Gemini judge Shared rubric Cost tracking

cardinal-portalNext.js 16

▾

The customer surface. Next.js 16 (App Router) + Clerk (auth, Organizations, Billing) + shadcn + Tailwind 4, deployed to Vercel. Owns sign-in/MFA, member management, Stripe subscriptions, dashboards, connector setup wizard, query UI, and the CE admin console.

Communicates with the Railway backend via Clerk-issued JWTs. The org.slug claim flows through to api/middleware/clerk_auth.py, which scopes every operation to that tenant's FalkorDB graph + Pinecone namespace.

04Productization Architecture

The product splits into two halves communicating via Clerk JWTs.

cardinal-portal (Vercel) Next.js 16 + Clerk + shadcn. Owns auth, MFA, Organizations, Stripe Billing, dashboards, connector setup, admin console.
Railway backend (FastAPI) Protocol execution, ce-graph queries, ingest workers, per-tenant cost tracking. Validates Clerk JWT via api/middleware/clerk_auth.py.
↓ Clerk JWT (org.slug claim)
Tenant scoping Clerk Organization → org.slug → ce-graph tenant slug. Runs persisted with tenant_id column. Per-tenant FalkorDB graph + Pinecone namespace.
Agent Builder Prompts, tools, memory
Orchestration 57 protocols, 62 agents
